# Binance USDT Perpetual Futures Trading Bot

자동화된 암호화폐 선물 거래 시스템. Binance USDT 무기한 선물 시장에서 멀티 타임프레임(MTF) 신호 분석과 동적 레버리지 조절을 통해 체계적인 스캘핑 및 트렌드 추종 거래를 수행합니다.

---

## 주요 특징

| 특징 | 설명 |
|------|------|
| **멀티 타임프레임 분석** | 15분봉 신호 + 일봉 HTF 필터 — 잡음을 줄이고 추세 방향성만 포착 |
| **동적 레버리지** | 신호 강도에 따라 2×~20× 자동 조절 — 고확신 진입일수록 높은 레버리지 |
| **헤지 모드** | Binance 헤지 모드 활용 — 롱/숏 동시 포지션 가능 |
| **매크로 레짐 감지** | BTC 일봉 기반 불/베어/횡보장 자동 판단 → 거래 심볼 및 전략 자동 전환 |
| **복합 신호 시스템** | 9개 카테고리(추세·반전·변동성·볼륨·ICT·VWAP·오더북·스퀴즈·모멘텀) 결합 |
| **Slack 실시간 알림** | 진입/청산/일일 브리핑 — 모든 타임스탬프는 KST |

## 거래 전략 — 쉬운 설명

### 1. 시장 상황 판단 (매크로 레짐)

거래를 시작하기 전, 봇은 먼저 BTC(비트코인)의 일봉(하루 단위) 차트를 분석해 현재 시장이 어떤 상태인지 판단합니다.

```
불마켓(BULL) : BTC의 50일 평균이 200일 평균보다 위에 있고 상승 모멘텀이 강할 때
               → 상위 10개 코인 전체에서 스캘핑 수행
               → 최대 20× 레버리지

베어/횡보(BEAR/SIDEWAYS) : 그 외 상황
               → BTC + ETH 2개만 거래 (손실 최소화)
               → 역시 최대 20× 레버리지 (빠른 반등 포착)
```

불마켓 판단은 **3번 연속 신호** 확인 후 전환 (잦은 전환 방지), 베어/횡보 전환은 **2번 연속** 확인.

---

### 2. 신호 감지 시스템 (9개 카테고리)

15분봉을 기준으로 아래 9가지 유형의 신호를 수집해 **방향(롱/숏)** 과 **강도(0~1)** 를 계산합니다.

| 카테고리 | 의미 | 지표 예시 |
|---------|------|----------|
| **추세(Trend)** | 현재 가격이 상승 추세인가? | EMA 9/21/50, ADX, 헐 이동평균 |
| **반전(Reversion)** | 과매수/과매도로 반전 임박? | RSI, StochRSI, Williams %R, RSI 다이버전스 |
| **변동성(Volatility)** | 변동성이 충분한가? | 볼린저밴드, 켈트너채널, ATR |
| **볼륨(Volume)** | 거래량이 방향을 지지하는가? | CMF(차이킨 머니플로우), OBV, 자금 유입/유출 |
| **ICT** | 스마트머니가 움직이는가? | 공정가치 갭(FVG), 오더블록, 시장 구조 변화 |
| **VWAP** | 현재 가격이 VWAP 대비 어디에 있나? | 거래량 가중 평균 가격 대비 위치 |
| **오더북** | 매수/매도 잔량 불균형이 있나? | 상위 5단계 매수/매도 잔량 비율 |
| **스퀴즈(Squeeze)** | 변동성 압축 후 폭발 직전인가? | 볼린저밴드 + 켈트너채널 스퀴즈 |
| **모멘텀(Momentum)** | 단기 모멘텀 방향은? | MACD, StochRSI 모멘텀 |

이 신호들을 **시장 상황(추세장/횡보장/고변동성)에 따라 가중치를 다르게** 결합해 최종 점수를 계산합니다.

#### 일봉 HTF 필터 — "나침반" 역할

15분봉 신호가 나왔더라도, 일봉 차트의 방향과 반대라면 진입하지 않습니다.

```
롱 진입 가능 조건 :
  - 일봉 EMA50 > EMA200 (골든크로스 구간)
  - 일봉 RSI가 40~70 사이 (과매도/과매수 아닐 때)

숏 진입 가능 조건 :
  - 일봉 EMA50 < EMA200 (데드크로스 구간)
  - 일봉 RSI가 30~60 사이
```

이 필터 덕분에 불마켓에서 롱:숏 비율이 **90:10** 수준으로 유지되어 추세를 따라갑니다.

---

### 3. 거래 모드 선택 (스캘핑 vs 트렌드 추종)

신호 강도와 시장 상황에 따라 **두 가지 거래 모드** 중 하나를 자동 선택합니다.

| 구분 | 스캘핑(SCALP) | 트렌드 추종(TREND RIDE) |
|------|--------------|----------------------|
| 목표 | 단기 빠른 수익 | 큰 추세 전체 포착 |
| 손절 | 1.2 × ATR | 2.0 × ATR |
| 1차 목표 | 2.5 × ATR (R:R 2.1:1) | 4.0 × ATR (R:R 2.0:1) |
| 2차 목표 | 5.5 × ATR (R:R 4.6:1) | 10.0 × ATR (R:R 5.0:1) |
| 1차 목표 도달 시 | 55% 청산 | 45% 청산 |
| 최대 보유 시간 | 12시간 (48 × 15분봉) | 60시간 (240 × 15분봉) |

**ATR(Average True Range)** 은 최근 14봉의 평균 가격 변동폭입니다. 예를 들어 BTC가 100,000달러이고 ATR이 1,500달러라면, 스캘핑 손절은 1,800달러 아래에 설정됩니다.

**1차 목표 도달 후**: 절반 이상을 이익 실현하고, 나머지는 손절을 본전으로 올려 **리스크 제로 상태**로 추세를 더 탑니다.

---

### 4. 동적 레버리지 — 확신이 높을수록 더 크게

```
신호 강도 ≥ 0.85 : stop을 0.35× 로 타이트하게 → 레버리지 ~20× (리스크 13%)
신호 강도 ≥ 0.80 : stop을 0.50× → 레버리지 ~15× (리스크 7%)
신호 강도 ≥ 0.75 : stop을 0.65× → 레버리지 ~8×  (리스크 3.5%)
신호 강도 ≥ 0.65 : stop을 0.85× → 레버리지 ~5×  (리스크 2.5%)
기본값         : stop을 1.0×   → 레버리지 ~3×  (리스크 1.5%)
```

레버리지는 `base_leverage = trade_risk_pct / stop_distance_pct` 공식으로 계산됩니다. 드로우다운이 커지면 자동으로 레버리지 상한이 낮아집니다 (>12% DD → 50%, >20% DD → 25%).

### 5. 리스크 관리 — 계좌 보호

| 규칙 | 값 | 동작 |
|------|-----|------|
| 1거래당 최대 리스크 | 자산의 2% | 레버리지 자동 조정 |
| 일일 손실 한도 | 8% | Slack 경고 (거래 계속) |
| 주간 손실 한도 | 15% | Slack 경고 (거래 계속) |
| 최대 드로우다운 | 30% | 거래 즉시 중단 (HALT) |
| 최대 동시 포지션 | 2개 | 자동 제한 |
| 최대 총 노출도 | 자산의 75% | 자동 제한 |
| 스프레드 임계값 | 0.3% | 시장가 주문으로 전환 |

**복리 성장 모드**: 일일/주간 손실 한도 초과해도 거래를 계속 유지합니다. 장기 복리 성장을 위해 일시적 손실에도 포지션을 유지하는 전략입니다. 30% 드로우다운만이 강제 중단 조건입니다.

### 핵심 설계 원칙

**Circuit Breaker**: API 실패 5회 연속 → 60초 쿨다운. 거래소 장애 시 주문 폭주 방지.

**GTX (PostOnly) 주문**: 진입 시 메이커(0.02%) 수수료 우선 사용. 즉시 체결 거부 시 GTC로 재시도. 손절/청산은 시장가(테이커 0.04%).

**트레일링 스톱**: TP1(1차 목표) 도달 후에만 활성화. 이전에는 진입 직후 소폭 반등에도 청산되는 문제가 있었고, `tp1_hit` 플래그 조건 추가로 해결.

**수수료 모델**:
- 진입: 메이커 0.02% (GTX 지정가)
- TP/TRAILING 청산: 메이커 0.02% (지정가 청산)
- 손절/강제청산: 테이커 0.04% (시장가 긴급 청산)
- net PnL = gross PnL - 총 수수료 (DB 및 Slack 모두 net 기준)

## 개발 배경 및 구현 역량

이 프로젝트는 단순 API 연동을 넘어, **실제 거래 수익을 목표로 설계된 프로덕션급 시스템**입니다.

### 해결한 핵심 문제들

1. **신호 방향성 문제**: 기존 5분봉 단일 타임프레임 전략은 불마켓에서도 롱:숏이 50:50으로 나뉘는 문제 발생. 일봉 HTF 필터 도입 후 **90:10 롱 편향** 달성.

2. **조기 청산 문제**: 트레일링 스톱이 TP1 도달 전에도 작동해 소폭 손실로 청산되는 문제. `tp1_hit` 플래그 조건 추가로 해결.

3. **유령 포지션 버그**: PostOnly 주문 거부 후 동일 ID로 시장가 재시도 → "ID 이미 존재" 오류를 체결로 오판 → 실제 없는 포지션 기록. 새 클라이언트 ID 생성 및 주문 상태 검증으로 해결.

4. **수수료 모델 정확도**: 진입/부분청산/완전청산 시 수수료를 독립적으로 추적, DB에 net PnL 저장.

### 아키텍처 의사결정

- **Circuit Breaker 패턴**: 거래소 API 장애 시 무한 재시도 방지
- **State Machine 패턴**: 포지션 상태(Flat/Long/Short) 전환을 명시적으로 관리, 엣지 케이스 처리 용이
- **SQLite WAL 모드**: 동시 읽기/쓰기 성능 향상, 스케줄러와의 충돡 방지
- **이중 타임프레임 전략**: 저주파(일봉) 방향성 + 고주파(15분봉) 진입 타이밍 분리
